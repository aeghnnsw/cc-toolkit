### Changed

- dev-skills (Claude Code 3.79.0, Codex 1.65.0, Antigravity 1.34.0): in t3-project-lead, `start` prints one line with the dev-skills version in each host manifest of the installed copy that it runs, so each lead session shows its version. See [#576](https://github.com/aeghnnsw/cc-toolkit/issues/576).
- core-hooks (Claude Code, Codex, and Antigravity 1.1.0): the stale-install check also runs at Codex session start and outside a cc-toolkit checkout, and is on by default, because an opt-in variable does not reach the sessions that T3 Code starts. It reports each stale install against the marketplace clone of the same home, and gives one command set to linked Codex homes. `CORE_HOOKS_STALE_CHECK=0` turns it off. Codex 0.172.0 runs a new or changed hook only after you trust it. See [#576](https://github.com/aeghnnsw/cc-toolkit/issues/576).
- Repository: the README Codex update steps say that `codex plugin add` removes the old version folder, so running Codex sessions must restart, and cover a home in `CODEX_HOME` and hook trust. The glossary adds installed copy, marketplace clone, and stale install. See [#576](https://github.com/aeghnnsw/cc-toolkit/issues/576).
